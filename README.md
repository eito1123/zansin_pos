# Zansin学祭POS

学祭の焼き鳥屋台で使う、iPad 向けの簡易 POS（Web アプリ）です。注文の中身（部位・タレなど）は紙伝票で管理し、このアプリではセット数の入力・会計・お釣り計算・売上の記録と集計を行います。

- 売上はまず各 iPad の中（IndexedDB）に保存します。**通信がなくても会計できます。**
- ログインしておくと、売上が自動でクラウド（Supabase）にバックアップされ、全端末の売上をまとめて見られます。
- サーバー側は Vercel（静的ホスティング＋API）と Supabase（データベース）の無料プランで動きます。

開発者・AI エージェント向けの構成やルールは [AGENTS.md](AGENTS.md)、クラウドの設定と SQL は [supabase/README.md](supabase/README.md) を参照してください。

## 画面と機能

| 画面 | できること |
|---|---|
| 数量入力 | 1〜4セットのボタンを押すと、そのまま会計画面へ。5セット以上はテンキーで入力して「お会計へ」 |
| 会計 | 金額を大きく表示。預かり金額を入れるとお釣りを計算（未入力なら計算せずに完了）。「クーポン −／＋」で枚数を入力 |
| 売上履歴 | 本日の売上・セット数・会計件数、全会計の一覧、取消（確認あり。取消済みは履歴に残り、集計から除外） |
| バックアップ | 端末名と共通パスワードでログイン、バックアップ開始、iPad 交換時の復元 |
| 価格設定 | 1セットの価格（初期値 350円）。次の会計から適用し、過去の売上は変わらない |
| 割引設定 | クーポン1枚あたりの割引額（初期値 50円）。次の会計から適用し、過去の売上は変わらない |
| 全端末の集計（`/dashboard.html`） | 全端末の売上合計、端末別・単価別・時間帯別の集計、売上明細の印刷 / PDF。閲覧専用 |

### クーポン
- 1枚につき1セットを、設定した割引額だけ割り引きます。セット数を超えた分のクーポンは「対象外」と表示し、適用しません。
- クーポン付きの会計だけ確認画面を出し、「確定する」で保存します。
- 例（350円・割引額50円）：1枚・1セット → 300円／2枚・3セット → 950円／3枚・2セット → 600円（1枚は対象外）

### 画面右上のバッジ
| 表示 | 意味 |
|---|---|
| ☁ 送信済み | バックアップ済み |
| ☁ 未送信 N件 | 送信待ち（オフライン中など）。通信が戻れば自動で送信 |
| ☁ 要ログイン | ログインが切れている。バックアップ画面でログインし直す |
| ☁ バックアップ未開始 | この端末で「バックアップを開始」をまだ押していない |

## 毎年の運用手順

### 準備（学祭の前）
1. **Supabase**：プロジェクトを作り、`supabase/migrations/` の SQL を**日付順にすべて**実行し、運営用ユーザーを1名作る（詳細は [supabase/README.md](supabase/README.md)）。
2. **Vercel**：GitHub のこのリポジトリからプロジェクトを作り、環境変数4つを **Production** に登録してデプロイする（[supabase/README.md](supabase/README.md) の表を参照）。
3. **テスト環境（任意・推奨）**：テスト用の Supabase をもう1つ作り、Vercel の環境変数を **Preview だけ**に登録する。別ブランチに push すると、本番に影響しない Preview で試せる。
4. **iPad**（レジごと）：
   1. Safari で**本番の固定 URL** を開く。デプロイごとに変わる個別 URL は使わない。
   2. 画面右上に「オフライン利用可能」が出るまで待ち、共有メニューから「ホーム画面に追加」する。
   3. ホーム画面のアプリから開き、売上履歴 → バックアップで、端末名（例：焼き台前レジ）と共通パスワードを入れてログインし、「この端末のバックアップを開始」を押す。
   4. 価格設定と割引設定を確認する。
   5. テスト会計をして、バッジが「☁ 送信済み」になり、全端末の集計に表示されることを確認する。テスト会計は履歴から取り消す。
5. プライベートブラウズでは使わない（端末内の保存が消えるため）。

### 会期中
- 各レジは、毎回同じホーム画面アプリ（同じ URL）で使う。
- 全端末の売上は、PC やスマートフォンで `/dashboard.html` を開いて確認できる（共通パスワードでログイン）。
- アプリを更新したときは、画面下の「最新版に更新」を、会計の合間に数量が未入力の画面で押す。
- **Safari の Web サイトデータは削除しない**（その端末の売上が消える）。

### 会期後
1. 各レジのバッジが「☁ 送信済み」（未送信 0件）になっていることを確認する。
2. 売上データを書き出す（CSV / JSON の SQL は [supabase/README.md](supabase/README.md) の「会期後のデータ書き出し」）。全端末の集計ページから全期間の PDF も保存しておく。
3. 書き出した件数がデータベースの件数と一致することを確認する。
4. 不要になったら Supabase のプロジェクト、Vercel のプロジェクト（または Preview の共有リンク）を削除する。**このリポジトリは残す**（翌年の引き継ぎ用）。
5. 最後に、各 iPad の Web サイトデータ（ホーム画面アプリ）を削除する。

## アプリの更新の仕組み

- `master` ブランチに push すると、Vercel が自動でビルド（`node build.mjs`）して本番にデプロイします。ビルドのたびに Service Worker のキャッシュ名が変わります。
- iPad は通信できる状態でアプリを開くと新しい版を取得し、画面下に「最新版に更新」を表示します。会計を終えて、数量が未入力の画面で押すと更新されます。
- 「最新版に更新」が出ない場合は、オンラインで一度開いて少し待ち、POS のタブやホーム画面アプリをすべて閉じてから開き直してください。

## 動作確認のチェックリスト

- 3セットをタップ → 3000 を入力 → お釣り表示 → 会計完了 → 履歴に表示される。
- 預かり金額が不足している間は会計完了を押せない。C で未入力に戻すと、計算せずに完了できる。
- 価格を変更 → 次の会計から新しい価格。過去の会計は元の金額のまま。
- クーポン：上の3つの例の金額になる。クーポン付きの会計だけ確認画面が出る。枚数を変えてもボタンの位置がずれない。
- 取消：確認でキャンセル → 変化なし。取消 → 履歴に残り、集計から除外。
- リロードやアプリの再起動後も、履歴・価格・割引額が残る。
- 「オフライン利用可能」の表示後、機内モードで再起動しても会計・履歴が使える。
- 全端末の集計に全レジが表示され、合計が各レジの履歴と一致する。印刷 / PDF の合計行が明細の合計と一致する。

## 開発

```bash
npm start   # http://localhost:4173
npm test    # 計算ロジックと API のテスト
```

ログイン用の Cookie は HTTPS 専用のため、クラウド機能の確認は Vercel（本番または Preview）で行ってください。ブラウザテストの実行方法やコードの構成は [AGENTS.md](AGENTS.md) にあります。

## よくあるトラブル

| 症状 | 原因と対処 |
|---|---|
| 新しい機能が表示されない | 古い版がキャッシュされている。「アプリの更新の仕組み」の手順で更新する |
| 「クラウド設定が未完了です」 | Vercel の環境変数が未登録・形式違い、または登録後に再デプロイしていない |
| 「保存済みデータとログイン先が異なります」 | その端末が以前、別の Supabase アカウントでバックアップしていた（ユーザーを作り直した、環境変数を変えた、Production と Preview の設定が違う、など）。データを移すのは手間がかかるため、不要なら端末内データとクラウドのデータを消して、全端末で同じアカウントからやり直すのが簡単 |
| 全端末の集計に、ほかのレジが出ない | そのレジでバックアップを開始していない、またはオフライン。バッジを確認する |
| 未送信の件数が減らない | オフライン、要ログイン、またはデータベースの SQL が未実行（新しい版を先にデプロイした場合）。バックアップ画面のメッセージを確認する |
| push したのに Vercel がデプロイしない | コミットに `Co-Authored-By:` 行があると、無料プランでは止まることがある。行なしのコミット（空コミットでも可）を push し直す |
| Preview の URL を開くと Vercel のログイン画面になる | Preview は Vercel のログイン保護がかかっている。デプロイ画面の「Share」で共有リンクを発行して渡す |
